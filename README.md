# 咬一口月亮 · 月饼配方 × 月相工坊

> 改一个配方参数，手里的月饼就变一个样子 —— 而它的缺口，始终是今晚月亮的形状。

## 它解决什么问题

大多数"月饼配方计算器"只给你一堆克数，跟画面毫无关系。
这个项目的重点是**让配方变成看得见的东西**：调皮馅比，断面上那圈饼皮立刻变厚变薄；换馅料，断面颜色跟着变；加一个蛋黄，剖面上就多一个蛋黄截面。

页面一打开就自动取本机时间与所在地，算出的月亮就是此刻抬头能看到的那一颗。

## 核心机制

### 1. 月相与咬口同构（双圆月牙）

咬口用的是**双圆月牙**模型：拿一个与月饼等半径的「咬痕圆」，沿一个方向咬进去，落在咬痕圆内的部分被咬掉。

```
保留区域 = 月饼圆 − 咬痕圆        （两圆等半径，圆心距 D）
交集面积 A(D) = 2·acos(D/2) − (D/2)·√(4 − D²)
令 A(D) = (1 − fraction)·π       → 二分反解出 D
  D = 2 → 两圆外切，什么都不咬（满月，月饼完整）
  D = 0 → 两圆重合，全咬光（新月）
```

两圆等半径时的差集正好是一枚月牙，而且**随 D 连续变化**——这是它能用的关键。

> 早先用的是月相的真实几何（终止线是半椭圆，判据 `u ≥ −k·√(1−v²)`）。
> 那个判据在圆盘上没问题，但圆柱面上 `u² + v² ≡ 1`，它会退化成恒等式：
> k 从 1 略减就把整个左半边侧壁切光，满月时又因浮点误差随机 discard，渲出一片细纹。
> 双圆模型没有这个退化，形状也更像"被咬了一口"。

咬口的数据源与月亮完全一致：`fraction` 决定咬多深，`angle` 决定从哪边咬。

### 2. 配方 → 渲染的映射

| 参数 | 画面上的变化 | 换算方式 |
| --- | --- | --- |
| 克重 | 月饼整体大小 | 重量正比体积，按 `∛(weight/75)` 缩放 |
| 皮馅比 | 断面上饼皮的厚度 | 解 `1 − (1−t)²(H−2t)/H = ratio`（二分法），即"皮体积占比"反推皮厚 |
| 蛋黄 | 断面蛋黄的数量与直径 | 沿断面水平排开（间距按馅料区宽度自适应），扁球截面 |
| 馅料种类 | 断面填充色 | 莲蓉棕 / 豆沙深褐 / 枣泥近黑 / 五仁土黄 |
| 月相 | 咬口深度与方向 | 与月亮同一份数据 |
| 切开开关 | 切掉靠镜头的一半、断面正对相机 | 随时看剖面，不受月相影响 |

### 3. 一个实心几何体，着色器分区上色

几何只有一个：把**月饼的截面形状**（含咬口）沿高度拉伸成实心柱体。
形状本身就是被咬过的轮廓，所以咬口处是**实心断面**，不是空壳。

所有面靠几何局部法线与半径在同一个 shader 里分区：

```
法线朝上        → 顶面，采样压花贴图（Extrude 的 cap UV 就是形状坐标，映射到贴图中心 84%）
法线朝下        → 底面，烤得最深
法线水平 r≈1    → 外壁，烘焙色渐变（底深 → 中部最亮 → 靠饼面一圈烤痕）
法线水平 r<1    → 咬口面 / 切开断面，按半径与高度画 皮 / 馅 / 蛋黄
```

### 4. 最圆时刻

在一个朔望周期内搜索照度极大值：6 小时步长粗扫锁定峰，再三级细化（窗口 7h → 20min → 1min），精度到秒。
页面显示「距最圆还有多久”，两个按钮可一键跳到上一次 / 下一次最圆那一刻，跳完自动把月亮区滚进视野。

注意：**不是每次满月都恰好 100% 亮**（月球轨道是椭圆），所以显示的是 99.9% 这类真实数值。

## 数据从哪来

这个项目**不依赖任何在线天文 API**。天体位置是**算出来的，不是查出来的**——NASA 自己的星历也是算的，不存在"更权威的一份表"。

| 内容 | 来源 | 精度 |
| --- | --- | --- |
| 月相、亮面比例与朝向 | `src/moon.js` 本地计算（基于 suncalc 的核心公式，MIT） | 与真实值差 < 1% |
| 月出 / 中天 / 月落 | 同一套公式 + 地平坐标变换 + 扫描插值 | 误差 1-3 分钟 |
| 最圆时刻 | 一个朔望周期内搜照度极大值，三级细化 | 秒级 |
| 农历（含闰月） | `vendor/lunar.js`（lunar-javascript，基于《寿星天文历》） | 与官方农历一致 |
| 月面贴图 | NASA 实拍（公有领域） | — |
| 月饼顶面 | AI 生成 | — |
| 定位 | 可选。IP 定位（ipapi.co → geojs.io），失败回落默认坐标 | — |

**为什么不用在线 API**：中国农历的官方发布方是紫金山天文台，但没有公开 API；NASA JPL Horizons、中国香港天文台这些有 API 的，实测在部分网络环境下连不通（返回 000）。而天文计算本来就应该本地算——更快、更稳、断网也能用。

唯一值得用权威数据的是**农历**（闰月与大小月规则复杂，自己推容易差一天）。所以引入了纯本地的 `lunar-javascript`，它内置《寿星天文历》数据，不联网、免费、无 key。

`node verify.mjs` 会把它和本文件的朔望月近似算法并排对照：

```
2026-09-25  权威 八月十五   | 近似 八月十五   一致
2025-10-06  权威 八月十五   | 近似 八月十五   一致
2025-08-01  权威 闰六月初八 | 近似 八月初八   ← 近似算法不处理闰月
2028-06-20  权威 五月廿八   | 近似 八月廿七   ← 差得更远
```

## 运行

### 方式零：直接下载免安装版

去 [Releases](https://github.com/sqdcz/bite-the-moon/releases) 下 `BiteTheMoon-1.0.0-portable.exe`，双击即用 —— 不用装、不用联网、不用配环境。

### 方式一：从源码跑桌面应用（推荐）

```bash
npm install     # 首次需要，会下载 Electron
npm start
```

窗口自己起来，不用浏览器，也**不需要网络**——three、农历库、字体、贴图全在本地 `vendor/` 与 `assets/` 里。

### 方式二：浏览器

项目用了 ES Module + importmap，**必须通过本地服务器打开**（`file://` 协议下模块请求会被 CORS 拦掉，页面直接白屏）：

```bash
python -m http.server 8080
# 打开 http://localhost:8080
```

### 打包成免安装 exe

```bash
npm run dist
# 产物：dist/BiteTheMoon-1.0.0-portable.exe —— 双击即用，无需安装
# 想要安装包（带开始菜单项）就跑 npm run dist:setup
```

打包出的 exe 约 90MB（Electron 运行时占大头），但完全自带、拷到任何一台 Windows 上都能跑。

## 自动从本机读取

- **时间**：启动直接取系统当前时间，点「回到此刻」随时刷新。
- **地点**：先静默走 IP 定位（ipapi.co → geojs.io，4.5s 超时，不弹授权窗），拿到经纬度立即重算月出月落；失败回落默认坐标。想更准点「用我的位置」。

## 踩过的坑（都已修）

**渲染与几何**

1. **相机不能固定在 +Z**。月亮的地心方向每天都在变，相机不动 → 看到的不是"朝地球的半球"，满月会显示成黑球。
   正解：把太阳方向投到「观察者在 +Z、+Y 指天极」的正交基里（`toScreenFrame`）。判据是"北半球盈月必右亮"。
2. **three.js shader 注入点必须是变量已定义处**。`outgoingLight` 要到 `#include <opaque_fragment>` 之前才存在，
   写在 `lights_fragment_end` 会让材质编译失败、物体直接不渲染，且**不会报错**，只是看不见。
3. **CSS 的 `display` 会盖掉 `hidden` 属性**。2D 兜底月饼一直叠在 3D 上面，导致怎么调 3D 都没变化。
4. **`texture.repeat > 1` 是缩小贴图**，不是放大。想让月饼顶满圆盘要用 `repeat < 1`。
5. **椭圆终止线的咬口判据在圆柱面上会退化**（`u² + v² ≡ 1`）。见上文「双圆月牙」。
6. **`LatheGeometry` 的模型旋转会让 shader 里的判据整体反向**。shader 读的是几何局部坐标，
   再套一层 `rotation.y = π` 就会把"保留靠镜头那半"变成"切掉靠镜头那半"。要挪接缝就用 `phiStart`，别转模型。
7. **几何和 shader 只能有一处负责裁剪**。形状已经切了一半，shader 又按 `z > 0` 切一次，
   结果只剩四分之一圆、画面偏到一边。
8. **`ExtrudeGeometry` 的侧壁顶点不共享**，法线是逐面算的，圆的侧壁会显出一圈棱。
   用 `toCreasedNormals(geo, π/5)` 焊接顶点、只在锐边断开法线。
9. **不要随手 `computeVertexNormals()`**。它会把顶面与侧壁交界处的法线平滑掉，shader 里的朝向判据跟着失真。
10. **`bevelEnabled` 会引入两个麻烦**：倒角面被朝向判据误判成顶面（采样到贴图的深色背景，形成一圈黑缝）；
    圆弧上的重叠面产生条纹。平顶圆柱反而干净。
11. **底面重合会 z-fighting**。馅料底与外壳平底原本都在 `y = −H/2`，渲出一片细密条纹。
    拉开 8‰ 就干净了；接触阴影平面也要离月饼底面足够远。
12. **开口的 `LatheGeometry` 外壳是无限薄的曲面**，切开后没有断面、也填不满。
    把「形状 = 月饼截面」的实心柱体作为唯一几何，断面天然是实心的。

**着色器细节**

13. **不要在 shader 里写高频 hash 噪声**。`fract(p.x * p.y)` 里 `p` 已经到几百，float32 精度撑不住，
    噪声退化成规律条纹。高频正弦也不行——在斜面上投影压缩会直接出摩尔纹。
14. **切口染色的判据必须避开退化点**。圆柱面上"到切口曲线的水平距离"恒等于 0，
    会把整片半边误染成馅料色，形成一条从顶到底的竖线。
15. **蛋黄排开方向要避开断面的常数轴**。切开时断面落在 `x = 0` 平面上，用 x 做偏移永远解不出蛋黄。

**取景**

16. **屏幕竖直方向的投影 = 高度×cos(俯角) + 纵深×sin(俯角)**。这两项很容易乘反，反了取景就一直偏松，
    只能靠经验系数硬补。切开后只剩远离镜头的半，目标点也要跟着移到 `z = −0.5R`。

## 已知取舍

- 农历用本地权威库（含闰月规则）；`src/moon.js` 里另留一套朔望月近似算法，只在库加载失败时兜底。
- 地平坐标用简化公式，月出月落误差 1-3 分钟，未做大气折射与地形遮挡修正。
- 咬口是双圆月牙，面积与真实月相的暗面比例严格相等，但形状略有差异（真实终止线是半椭圆）。
- 月饼侧面是程序化渐变 + 环境反射，没有烘焙纹理（想更好看可以再补一张侧面素材）。
